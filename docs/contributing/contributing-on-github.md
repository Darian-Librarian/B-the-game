# Contributing on GitHub

All technical development for the **B** ecosystem is centralized within the **[b-Universe](https://github.com/b-Universe/)** organization. Our primary repository for the game and the wiki is **[b-the-game](https://github.com/b-Universe/b-the-game)**.

---

## Project Direction

We're building a high-performance, grind-heavy simulation with a focus on a **16-bit**, **32-bit**, low-poly digital aesthetic. The goal: keep everything fast, efficient, and visually gritty.

### The Tech Stack

* **JavaScript**: Our primary choice for core simulation logic and the rewards engine.
* **DenizenScript**: Used for our custom Minecraft accessories and bridging the game to our API.
* **AutoHotkey (AHK) 2.0**: Strictly for automation efficiency, multiboxing macros, and workflow tools.
* **CSS/HTML**: Maintaining our **Dark**, **Dim**, and **Ecstatic** themes within the archive.

---

## Issues & Task Tracking

We use GitHub Issues to track what needs work. Find the full directory of our [**Issue Labels here**](contributing/issue-labels), but note these:

* **📃Documentation**: For when the wiki needs a touch-up or new pages added.
* **📃To-Do**: Tasks that are ready for someone to grab and finish.
* **✨Enhancement**: Refinements or optimizations for existing features rather than proposing new functionality.
* **✨Feature Request**: For proposing new mechanics or additions to the world.
* **↩️Follow-Up**: Used once a Pull Request is submitted to let us know it needs a final verification.

---

## The Workflow

Ready to push some code or add some lore? Follow this process:

1. **[Fork](https://github.com/b-Universe/B-the-game/fork)**: Hit the fork button to create your own branch of the repository.
2. **Setup**: Clone your fork locally and make sure you're using **VSCode** for editing.
3. **The Standards**: Double-check your indentation. We use a strict **two-space** rule.
4. **NLAEOF (Cursor Parking)**: Always leave a **New Line At the End Of the File**. On the **Live Server**, this gives us "parking space" for our cursors so we don't bump into each other's code while hot-loading scripts.
5. **Pull Request**: Once your changes are clean, submit a PR for review by **Bear** or **Darian**.
